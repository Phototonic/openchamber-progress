# Design

## Shell and view ownership

Keep `ProgressShell` as the common header and navigation owner, with the board placing Settings in the library bar and the rail placing it beside the plan chooser. Instantiate the existing menu interaction for the two differently named buttons; only one popup is open at a time. Return panels and confirmations to their actual opener. Settings is independent of successful plan reads. Keep the rail's quiet filter with plan choice, outside both menus, operable even with one or no choices. Do not add a fake plan option to a listbox.

Use the existing summary controller for both visible buttons: **Copy update** opens the progress preview; **Handoff note** opens the handoff preview. Neither writes to the clipboard on opening. Keep eligible single-plan Archive/Restore and Delete controls at the existing contextual cleanup mount below the plan, using its inline rendering instead of contributing items to More. Keep Delete separate, its explanation, safe initial focus and confirmation intact. Only the board gets bulk cleanup.

Use one view selection per frame. The default-view owner already understands four view values: retain its Map/List opening rules and latch an explicit selection even if detail arrives late. Do not keep a second competing Document/History route or duplicate header from the board's older tab branches. Keep the four segments reachable while reading any of the four views. Document Back and unhandled Escape return to the view it replaced, with focus on its Document selector. Sessions and service panels are temporary excursions, not fifth or sixth segments. The map renderer still owns its tools, canvas and task handoffs; it accepts the shared view switch now. On a narrow rail give the switch the row and let the tools follow.

Both History views call the existing bounded selected-plan history reader on demand. Keep the board's eligible pinned digest above Revisions, new-history indication on the History segment, explicit review, Refresh and View current task. The rail shows Revisions only; do not instantiate a digest, read a review point or import board search into the rail. List Activity remains its own collapsed visit. Leaving a view must end its active digest, comparison, activity or map work under the existing lifetime rules; retaining a position is not retaining an active reader.

## Board controls and counts

Keep the search field and its Filters trigger together: Filters owns Current/Archived, project/worktree/session choices, plan/task status, applicable source, scope/help and explicit submit. Moving Hide quiet beside the field uses the existing shared device preference; it does not narrow attention. Keep the search draft, composition, caret and native dropdown behaviour through repaint. The sidebar keeps its retained list container, keyed project listboxes, Finished folds, visible lifecycle/source qualifications and per-row attention. Count active lifecycle rows in the displayed browse scope, not all non-folded rows (failed is not active); qualify loaded-only counts, and keep the existing search count semantics in results.

Put **one** library-scoped Tidy beside the Finished area. With several project folds, place it at their library-level edge, outside any particular project's button/listbox, and identify that it covers closed plans in the board's current scope. Never repeat a library-wide destructive entry as though it acted on one project. When there is no visible Finished group (including search, Archived, empty or picker layout), use the equivalent list/results end control. Moving its opener does not change the counted target set, including eligible failed plans, or revive stale search actions.

The board top-bar count and expanded list project the same existing verified-source inbox. Count eligible, visible-on-device **items**, not plans, not all blocked tasks, not just loaded sidebar rows. Use authoritative counts during continuation/recheck; do not sum row badges. One disclosure opens the existing inline list beneath the bar, initially All plans, with This plan available for a selection. Changing the list filter never changes the global count or the selected plan. No inbox remains beneath the board plan. Keep hidden-item access in the inbox itself, including when every item is hidden; no duplicate More entry. Preserve the rail's session-first disclosure. Reuse saved expansion as-is; without a saved choice the board starts with the count, not an open list. Do not open over the user's focus on a background update.

## Reading and visual stability

Keep the Back action and the **returned capture's** filename on a single document header line; fall back to the localized Document label without a filename. Use a short localized age such as “Saved 22 h ago” from `capturedAt`, not `checkedAt` or the report time. Keep current-file-not-rechecked, synchronized, failed-check/last-good and historical-race facts visible when applicable, in short separate facts rather than a new notice. Do not shorten away a warning or turn an old capture into a current-file claim.

Let the long Markdown or literal body scroll within the remaining guest height, adapting to shorter and taller frames, insets and the keyboard. Do not exchange 420 px for another fixed ceiling. Leave Back, capture facts, Retry and the board-only comparison reachable in short windows. Contain horizontal overflow at each wide table; keep table headers, cells and keyboard scrolling available. Rendering, parsing budgets, inert content, link handling and literal comparison are unchanged.

Extend the frame's existing task-row anchor, map viewport and repaint scroll restoration rather than storing rendered nodes or captured bytes. Keep only Map, List and Document positions for the **current** reading (account, store/binding, surface scope, source-qualified plan and cleanup generation), invalidated by a newer capture, not every progress revision. A loading paint must not overwrite a saved position with zero; restore only against matching rendered content. Clamp to surviving content. Explicit task jumps, focus returns and new-reading defaults take precedence over passive scroll restoration. No cross-plan history of positions, device writes, timers or extra reads.

Use the existing host tokens and shared surface/phone styles; scope changes away from Work Status. Establish a small set of title, body and secondary text sizes, common control heights and spacing. Reserve the progress legend's natural line space while task detail is pending, without dummy data or announcements. Allow reflow before hiding essential text; never shrink touch targets to keep tools on one line. Keep visible focus and selected states, including system colours in forced-colour mode.

## Compatibility and rollback

Older services retain their existing capability gates and unavailable states. No migration or coordination between guests is needed. Other than the first-use expansion default, persisted preferences are interpreted as before; previously saved values remain valid in either guest. Reverting the presentation and its navigation instructions restores the former layout without changing plans, captures, review points or stored preferences.
