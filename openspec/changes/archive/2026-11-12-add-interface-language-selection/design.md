# Design

## Context

Мотивация — [proposal.md](proposal.md); наблюдаемое поведение и критерии — [interface-localization](specs/interface-localization/spec.md). Это сквозное изменение guest UI, а не backend или progress-протокола.

### Проверенная база реализации

Проверенная база на 2026-11-12 — `b0f3805`, package 1.1.1. Локализация уже реализована в `294d3e6`, описана в `fb67190` и исправлена в `bd55769`/`fa81341`; это актуализация design существующего поведения, а не план первой реализации. Историческая pre-apply база `c0d9a9ab`/`ad9e4816` больше не описывает runtime. Контракты поведения остаются в [docs/ui.md](../../../../docs/ui.md) и [docs/contracts.md](../../../../docs/contracts.md).

Согласно [CONTRIBUTING.md](../../../../CONTRIBUTING.md#local-development), принимаются Node 24.x >= 24.19.0 и Bun 1.3.14; 24.19.0 — проверенный baseline, более новые 24.x не сертифицированы отдельно. Доступность обоих инструментов подтверждена, но не означает прохождения runtime-тестов. Явный запуск `mise exec node@24.19.0 bun@1.3.14 -- <команда>` остаётся допустимым без изменения глобальных настроек. Версия OpenSpec для валидации артефактов проверяется отдельно от runtime toolchain.

Подтверждённые точки интеграции:

- `package.json` закрепляет `@openchamber/sdk` 2.7.0. Его `API.md`, раздел Extension storage, определяет `undefined` как отсутствие записи, `null` как записанное значение, `{scope:'device'}` и обязательный `features.deviceStorage === true`. Storage без options — серверный и для языка непригоден. Используются SDK-компоненты и стандартный `Intl`, без новой библиотеки переводов.
- `ui/shared/app.ts` создаёт каждый frame, передаёт уже эффективный язык в `Env.locale` и ticker, обновляет данные через один `RefreshGate` (3 секунды, после ошибки 8 секунд), приостанавливает таймер при скрытии. `spec.refreshed` вызывается только после успешного progress-read и не подходит для синхронизации языка при недоступном сервисе.
- `ui/panel/main.ts` имеет ранний выход без `read`; `ui/page/main.ts` уже рисует служебную область без данных. Поэтому переключатель нельзя привязать к успешному чтению или наличию выбранного плана. Work Status остаётся без собственного переключателя.
- Каталоги EN/RU распределены по существующим владельцам текста: форматтерам, моделям, проекциям, контроллерам и renderer. Исторические зависимости digest от `Refreshing…` и карты от английских singular regex устранены; состояние и структурированные факты отделены от перевода.
- `summary.ts` — чистые детерминированные Markdown-форматтеры. `app.ts` удерживает результат/исторический снимок preview и учитывает язык при reuse. Clipboard захватывает показанную строку и ограждает feedback поколением. `tests/browser/preview-summaries.test.ts` фиксирует точный английский вывод.
- Восстановление disclosures сохраняет готовое/ошибочное состояние без повторного document-read; repaint не является разрешением на I/O. `source.ts` уже категоризирует health `corrupt/schema/busy/storage` для безопасных UI-подписей: это существующее поведение сервиса, не новый endpoint локализации.

## Goals / Non-Goals

**Goals:**

- Отделить сохранённый режим языка, вычисленный язык и состояние чтения/записи; сделать перевод presentation-only операцией поверх существующих проверенных данных.
- Использовать один механизм для трёх frames, SDK device storage и имеющиеся repaint/focus/scroll/map seams. Сохранить внешние контракты и точный английский формат summaries.
- Выпустить цельный перевод всех принадлежащих расширению поверхностей без промежуточного публичного режима с частично русским интерфейсом.

**Non-Goals:**

- Перевод текста пользователя, поисковых запросов, содержимого документов, CLI/companion, package metadata и host-owned chrome, включая названия разделов хоста и его clipboard/toast-кнопки.
- Новая библиотека i18n, динамические словари, загрузка переводов, автоперевод, дополнительные языки, серверная настройка, cross-device sync, CAS, новый endpoint или подписка хоста.
- Перенос остальных UI preferences в device storage, изменение review checkpoints, readiness, порядка задач, безопасности экспорта или разрешений на действия.

## Decisions

### 1. Два языка и явный presentation-контекст без глобального изменяемого переводчика

`ui/shared/i18n.ts` определяет `LanguagePreference = 'auto' | 'en' | 'ru'`, `InterfaceLanguage = 'en' | 'ru'`, чистое разрешение языка и типизированный каталог переключателя. Остальные локальные EN/RU-каталоги и helpers принадлежат существующим UI-модулям, а не единому каталогу всего текста. Составные сообщения задаются целыми фразами с именованными параметрами/функциями, а не склейкой английского порядка слов. Полноту обеспечивают локальные типы и проверки соответствующих поверхностей, а не единая глобальная схема.

В автоматическом режиме `Intl.getCanonicalLocales` валидирует host tag; язык `ru` с любым корректным региональным вариантом даёт `ru`, всё остальное — `en`. Явный режим не зависит от host locale. Для форматирования используются эффективные `en`/`ru`, а не произвольный регион хоста; регионально-точное форматирование вне объёма. До первого успешного чтения действует auto; автоматическая запись этого значения не выполняется.

Presentation-контекст передаётся через существующий `Env`/`ViewContext` и явно в чистые форматтеры/текстовые helpers. В существующих чистых публичных UI-helpers допустим default `en`, чтобы сохранить текущих вызывающих и точные тесты; production-вызовы передают эффективный язык. Вызовы `resolveLanguage('auto', env.locale)` в renderer нормализуют уже эффективный `en`/`ru`, а не заново выбирают host preference. Нет импортов SDK/DOM в каталог и нет перевода в wire adapter. Контроллеры передают семантические коды и параметры для перевода при показе без изменения их семантики.

Альтернативы: глобальный mutable singleton скрывает зависимости и смешивает языки тестов; полноценный i18n framework добавляет зависимость ради двух статических каталогов. Оба не нужны. DOM-постобработка английских строк также отвергнута: она не покрывает callbacks, aria и новые фразы и рискует перевести данные пользователя.

### 2. Один маленький device preference вместо схемы review checkpoints

DOM-free `ui/shared/language.ts` владеет чтением/записью фиксированного ключа `interface-language.v1` со значением `{v: 1, preference: 'auto' | 'en' | 'ru'}`. Допустимы только эти два поля и значения; `undefined` означает отсутствие, `null`, другой version/type и лишние поля — повреждённую запись. Автоматически исправлять/перезаписывать её нельзя. Ключ не содержит account, plan, session, store или source: partition уже предоставляет хост.

Контроллер хранит последний подтверждённый режим (либо отсутствие), отдельное состояние ошибки чтения и записи и pending-запись. Вычисленный язык не сохраняется. Тексты ошибок фиксированы и локализованы, сырой storage error не показывается. Ошибка чтения оставляет последний подтверждённый режим, при его отсутствии auto; ошибка записи не меняет режим и допускает повтор через переключатель. Успешное последующее чтение/запись снимает соответствующую ошибку. При подтверждённом отсутствии извне режим возвращается к auto без записи.

Если feature отсутствует/выключена, новые storage requests запрещены, эффективный режим auto, ручной выбор отключён с доступным объяснением. При повторном объявлении поддержки выполняется чтение, а не восстановление неподтверждённого предположения. Не использовать instance storage, `localStorage` или временный per-frame override. Историю checkpoint-ключей, их хеши, enumeration и compaction не переиспользовать: обычная заменяемая настройка языка не монотонна.

### 3. Согласование на существующей cadence, отдельно от успеха progress

```text
HostReady(locale, features) --> language controller --> presentation context
                                     ^                       |
existing RefreshGate / focus / visible|                       v
                              device storage          panel / page / status
                                                     + pure summaries
```

`startView` создаёт контроллер после подключения SDK. Первый ready и изменения locale/features пересчитывают presentation; чтение настройки выполняется на ready, в начале каждого видимого прохода существующего refresh до любого `await` progress/search, на focus и visible. Storage-read не ожидается перед progress-read и его отказ не меняет состояние сервиса. Focus-only перечитывает настройку, не инициируя progress retry. Совпавшие focus/visible/poll объединяются; одновременно допускается одно чтение. Новых таймеров и device subscriptions нет.

На локальный выбор сразу инвалидировать начатое ранее чтение. Одновременно допускается одна запись: контрол отключён только на время записи, повторные activation не отправляют новые set. Применять новый режим после успешного `set`, затем разрешить последующие чтения. Запоздалое чтение не отменяет собственный подтверждённый выбор; следующий обычный read приводит frame к фактически сохранённому значению. Между frames применяется итоговая атомарная запись storage, без обещания порядка по времени кликов и без клиентских timestamp/revision.

Скрытый frame не начинает проверки; скрытие и disposal делают held callbacks неактуальными для UI, visible начинает свежую проверку. Уже отправленный `set` может завершиться и сохранить только захваченное значение: его нельзя отменить обещанием. Если frame вернулся до завершения записи, `finally` снимает pending и разблокирует select, даже когда retired-результат не принимается как подтверждённый выбор; затем выполняется свежее чтение. Language preference не сбрасывается при смене account, progress store/source, плана или проекта и не входит в их identity. Новый runtime/installation получает собственный namespace от хоста.

Ограничение: cadence зависит от завершения существующего refresh; мгновенная доставка между frames не обещается. Focus/visible позволяют проверить язык независимо от зависшего progress-read. Это меньше и безопаснее отдельного poller или неподдерживаемого broadcast-протокола.

### 4. Один SDK-переключатель в служебной области и presentation-only repaint

Общий renderer в существующем `components.ts` использует `mountSelect`, со стабильным `data-testid="interface-language"`, локализованной подписью Language / Язык, option IDs `auto/en/ru`, названиями English и Русский на самих языках и локализованным «Язык OpenChamber». Ошибка/unsupported-пояснение располагается рядом, связано через доступное описание; результат операции объявляется обычным status без вывода произвольных ошибок. Флагов и нового modal нет.

Panel и page рисуют контрол ровно один раз в нижней служебной области независимо от ранних выходов, до/без setup, плана, read или health. Существующие Setup/Details остаются по своим правилам — ради языка не создавать их новые дубликаты. Work Status только применяет общий presentation-контекст и пояснение ошибки/отсутствия поддержки там, где оно необходимо, без select и нового header control.

Language update меняет только presentation version, не `initialUi`, reading identity, cache generation или navigation hooks. Сохраняются план, tab, фильтры, введённый поиск, раскрытия (включая внешний update при фокусе другого frame), выбранная задача карты, pan/zoom и focus/scroll по существующим seams. Внешний update использует background repaint с существующим deferral независимого SDK popup; локальный выбор после закрытия select сохраняет фокус на его trigger. Фокус другого frame/control не перехватывается. После `applyHostReady` `document.documentElement.lang` устанавливается на эффективный язык; host context не изменяется. Ticker и visible refresh labels используют тот же язык, включая неизвестное время и tooltip.

Восстановление document disclosure должно заполнять готовое/ошибочное состояние без повторного request; повтор разрешён явным открытием/retry или обычным data lifecycle, не переводом. Аналогично repaint не начинает новый digest/search/map/diagnostic visit и не пишет review checkpoint. Семантическое состояние сообщений остаётся прежним; объявления переводятся без повторного выполнения действия.

### 5. Полный охват строк и форматирования без перевода машинных значений

Владельцы локализованного текста и границы ответственности:

| Область | Файлы и ответственность |
| --- | --- |
| Lifecycle и основные поверхности | `ui/shared/app.ts`, `ui/{panel,page,status}/main.ts`, `ui/shared/components.ts`, `style.ts`: footer, состояния, focus notices, picker/tab labels, clipboard feedback и layout |
| Общий текст и значения | `format.ts`, `model.ts`, `primitives.ts`, `readiness.ts`, `live.ts`, `scope.ts`, `progress-projection.ts`, `ui/status/projection.ts`: status/lifecycle/document/readiness/live labels, доступные имена, количества, длительности |
| Дополнительные поверхности | `setup.ts`, `official.ts`, `cleanup.ts`, `cleanup-view.ts`, `search.ts`, `search-view.ts`, `change-digest.ts`, `change-digest-view.ts`, `capture-comparison-view.ts`, `census-view.ts`, `subagents.ts`, `reporting-health.ts`, `reporting-health-view.ts`, `dependency-map-view.ts`, `dependency-map-interaction.ts`: служебные фразы и сохранённые сообщения; соответствующие controllers менять только там, где они действительно создают текст |
| Экспорт | `summary.ts`, task Copy details в `components.ts`, summary lifecycle в `app.ts`; `source.ts` сохраняет машинные failure kind/code, presentation переводит их фиксированные описания, а не произвольный error.message |
| Проверки и документация | `tests/browser/*`, `tests/fixtures/preview-summaries.ts`, `docs/ui.md`; `i18n.ts`, `language.ts` и целевые language fixtures/tests/QA |

Существующие фильтры/решения сравнивают коды, не переведённые названия. Digest state machine и числовые формы карты больше не зависят от английского текста; добавление русских regex вместо семантических фактов не требуется.

`DependencyMapInteraction.select` передаёт renderer структурированные факты announcement с пользовательским title и числами, не готовую строку для перевода. Поиск сохраняет literal title только с provenance того же session ID; при смене выбора используется label самого `selectedOption`, включая сессии только из результатов поиска. Сгенерированные root-session/main-checkout labels следуют языку, записанные имена остаются literal, в том числе после reload или исчезновения option. Используются существующие `ViewSpec.prepareUi/preserveFocus/retire` и in-place `refreshLabels`; язык не становится новым navigation context.

После первой реализации карта получила сворачиваемую справку, снятие выбора и широкий inspector, легенду стрелок и сводки незавершённых prerequisites. Их собственный текст входит в локализацию, но геометрия, motion gates, selection и service I/O не меняются. Семантика стрелок остаётся в [dependency-map-arrow-state](../../../specs/dependency-map-arrow-state/spec.md), без передачи владения этой change.

Sub-agents локализует Partial, датированные loss warnings, статусы и явную кнопку dismiss. Серверная authority и действие `runs.ts` остаются в [subagent-loss-notices](../../../specs/subagent-loss-notices/spec.md): возраст/attention, sequence и результат dismissal не выводятся из языка. Перевод не инициирует GET/POST, reconcile или dismiss и не равен явному снятию предупреждения.

`Intl.NumberFormat`, `DateTimeFormat`, `RelativeTimeFormat` и `PluralRules` решают форматирование без новой зависимости; каталоги определяют формы one/few/many/other. Граничные случаи включают 0/1/2/5/11/21, короткие единицы, unknown, zero и invalid duration. Видимые количества карты используют `formatCount` для RU (`1000` → `1 000`, U+00A0), EN сохраняет raw decimal; машинные `data-count` и revision IDs не форматируются. Меняются только подписи, не числа, пороги времени или расчёт задач. Копируемые machine IDs, literal paths и коды остаются как записаны. Support payload из `supportSummary()` остаётся побайтово тем же при одинаковых фактах; его surrounding UI переводится.

### 6. Summary переводится из удерживаемого снимка, не перечитывается

`formatProgressUpdate`, `formatHandoff`, `formatSummaryOnly` и безопасное `describeDetailFailure` принимают язык с default `en`; остаются чистыми. Порядок секций/элементов, Markdown escaping, LF, UTC ISO timestamps, ограничения раскрытия, omissions и правила полноты не меняются. Английские golden fixtures сохраняются без переписывания ожиданий ради новой реализации. Русский имеет отдельные точные fixtures; неизвестные diagnostics дают только фиксированную безопасную фразу.

Preview хранит язык сформированного текста наряду с удержанным `result`/historical snapshot. При effective-language change переформировать из этих же данных, включая выбранный summary-only; условие reuse учитывает язык, а не только identity объекта. Не создавать `freshPreview`/`loadDetails` только ради перевода. Loading/error message тоже переводится. При изменении показанной строки увеличить preview generation, очистить selection/copy status; прежний clipboard-write завершает только захваченный текст и не подтверждает новый preview. При auto → explicit того же effective language без изменения строки поколение текста не меняется.

Task Copy details тоже переводит собственные подписи, сохраняя тот же набор показанных фактов; использовать имеющийся text/generation guard в `components.ts`. Никакого автоматического копирования при смене языка.

## Risks / Trade-offs

- [Широкий охват и пропущенная aria/отложенная фраза] → локальные EN/RU-каталоги, инвентарь поверхностей и rendered QA состояний на двух языках; не выдавать отсутствие английских букв в пользовательском тексте за критерий полноты.
- [Перевод ломает логику или создаёт I/O при repaint] → семантические коды отдельно от фраз, счётчики запросов/записей в fixtures, ошибочный открытый документ, открытая History и map/search в регрессиях.
- [Storage недоступен или более старый host] → auto и явное локализованное сообщение; никаких server fallback и неподтверждённых сохранений. Начальный auto может кратко смениться после асинхронного read; не блокировать progress на storage.
- [Конкурирующие frames] → атомарная последняя сохранённая запись и последующее перечитывание; не обещать latest-click-wins или мгновенную согласованность.
- [Русские строки шире английских] → SDK controls и переносы, проверки 190 px Work Status, 280 px rail, page и reflow 200%/400%; существующий height-sync остаётся активным.
- [Изменение языка экспортируемого текста] → документировать выбранный язык как часть presentation, сохранить точный English и machine payload, не обещать англоязычным парсерам русскую совместимость.
- [Неизвестная поддержка в реальном хосте] → установленный SDK и isolated fixtures не доказывают native-host интеграцию или screen-reader совместимость; эти проверки отмечаются отдельно.

## Завершение после проверки соответствия

Продолжение согласовано отдельно от исторической реализации: задачи утверждены и apply разрешён владельцем. Ниже зафиксированы причины и границы исправлений; их фактический статус и результаты приёмки определяются новыми пунктами [tasks.md](tasks.md), не историческими 19 галочками.

### Объявление результата скрытия предупреждения

До исправления в `census-view.ts` `announceLoss()` дедуплицировал исход только по `lossOutcome`, хотя постоянный live region находится вне перерисовываемого root. Поэтому тот же токен ошибки при смене языка оставлял английский текст. Воспроизведение фактической функции подтвердило расхождение; это не отсутствие перевода в каталоге.

Исправление разделяет идентичность операции и сформированный текст объявления: неизменные исход и текст не обновляются, а другой язык актуализирует текст без вызова `dismissLoss`. Поколение отложенной записи через `requestAnimationFrame` принадлежит последнему обновлению текста, поэтому старый callback не восстанавливает прежний язык. Сохранены один существующий live region и повторные отдельные ошибки; новый controller или service-действие не добавлены. Регрессии `interface-language-followup.test.ts` исполняют production-код и проверяют тот же токен при en → ru, отсутствие повторного объявления при неизменном repaint и доставку callbacks в обратном порядке.

### Номера ревизий — не количества

Общий `say()` в `components.ts` форматирует числовые параметры через `displayCount`. Ранее `historyBlock` и `detailsBlock` передавали номера `revision`/`structuralRevision` числами и получали русскую группировку. Исправление ограничено этими вызовами: номера переданы строками, локализация настоящих количеств сохранена; общий formatter и wire/model-типы не меняются. `interface-language-followup.test.ts` исполняет настоящие History/Details renderer и различает номера и количества при значениях не меньше 1000.

### Воспроизводимая reading QA и новые раскрытия

Начальное ожидание строки плана не доказывает завершение detail pagination; текущая телеметрия не позволяет приписать второй `/v1/plan` именно переводу. Result-only timeout также требует отдельного наблюдения query, ответа и показанного состояния. Сначала воспроизвести каждый сбой и проверить границы готовности; не заменять assertions задержками, пустыми проверками или широким исключением запросов. Если ошибка в QA — исправить её ожидание/синтетическую фикстуру, сохраняя исходный поведенческий оракул. Если ошибка в UI — закрепить её red-тестом и исправить первопричину в пределах контракта локализации. Не связанные с ним продуктовые изменения требуют отдельного решения.

В существующую изолированную QA добавить смену языка при открытой справке карты, выбранной задаче и раскрытых coverage/loss notes. Проверять сохранение раскрытий, selection/pan/zoom и отсутствие вызванных только переводом read/reconcile/dismiss, включая доступный текст результата скрытия предупреждения. Никакого live-профиля, модели или изменения основного spec карты/потерь записи. При недоступной инфраструктуре сохранить конкретный blocker; непроведённую проверку не отмечать успешной.

## Migration Plan

1. Основная возможность уже реализована; найденные несоответствия исправляются в её существующих границах. Прогресс, checkpoints и server storage для языка не мигрируются; отсутствие ключа языка означает auto. Подготовка артефактов не меняет код или generated outputs и не разрешает реализацию или публикацию.
2. Последующие исправления сохраняют поведение через содержательный red/green-тест и обновляют контракт `docs/ui.md`, если меняют его. Структурный перенос текста не должен менять семантические состояния и внешние действия.
3. Для будущих source changes нужны релевантные root/UI typechecks, browser regression и isolated rendered QA; существующим `bundle:guest` регенерируются только затронутые guest entries (все три лишь при общем изменении, затрагивающем все frames). Документационная правка не требует сборки. Backend/companion build и version bump не следуют из локализации. Проверки можно запускать через указанный выше явный `mise exec`.
4. Откат на развившемся дереве — минимальный совместимый UI-only patch, а не wholesale revert исходного runtime commit. Данные прогресса, run records и `interface-language.v1` не удаляются; повторное включение той же версии читает сохранённый выбор. Это не делает старый binary безопасным для run-format 2: совместимость и backend migration регулируются отдельными контрактами, без down-migration ради отката языка.

Карта проверок включает language/controller/format/summary suites и изолированную rendered QA, описанную в `docs/ui.md`. Исторические 19 выполненных задач не являются свежей приёмкой текущей базы. Фактические результаты повторного запуска и непроверенные сценарии фиксируются в [tasks.md](tasks.md); наличие теста не означает его успешное выполнение или полное покрытие более поздних поверхностей.
