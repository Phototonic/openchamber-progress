# Capture that comes with the extension, and progress you can hand to the agent

## New

- **Capture: installing Agent Progress now installs capture too.** OpenChamber loads the companion into the OpenCode it runs for you, so there is no separate global OpenCode plugin to install or remove. In Setup you confirm once where progress is stored. Disabling or removing the extension stops capture, and your recorded history is kept. If you run OpenCode with your own `OPENCODE_CONFIG`, capture keeps going until you restart OpenCode.
- **Composer: mention a plan with @ to hand its progress to the agent.** Typing `@` offers an **Agent progress** section of your plans. Picking one attaches a chip with a short summary of that plan's reported progress, so a new or compacted session can carry on without you pasting anything. The summary says it is reported progress as of a given time, not verified completion.
- **Sessions: Insert handoff and Insert progress update.** From a session's menu, these put that session's plan summary into the message box of the chat you have open, for you to read and edit. Nothing is sent for you. In OpenChamber 2.7.1 they are under the session menu's **Export** submenu.
- **Interface: choose English or Russian.** The rail and the fullscreen board have a language setting: follow OpenChamber, English, or Russian. Work Status follows the same choice. Plan and task titles are never translated. (thanks to [@Vnuchoke](https://github.com/Vnuchoke))
- Chat: calls to the progress-report tool show their own checklist icon and the name "Agent progress report". The tool's reply is shown as it is, so a refused or partly applied report is never dressed up as a success.

## Improvements

- Updates: updates now come from OpenChamber's own **Settings → Extensions**, and Agent Progress no longer shows its own version notice. The check behind that notice was the extension's only network call, so the extension now makes none. An ordinary update keeps your permissions, settings, store and history; an update that asks for more access shows OpenChamber's approval dialog first.
- Setup: Setup and Reporting health show separately whether capture is set up, whether it is switched on, whether the companion has been seen loading, and when the last report arrived. They also warn when the loaded companion is not the one this version expected.

## Fixes

- Setup: when something is wrong with an old Setup install, you can still switch capture off. Busy or unreadable data is reported as such and can be retried, instead of being shown as an ownership problem.

## Misc

- **Requires OpenChamber 2.7.1 or later.** This is the first version with mobile extension support and the one this release was tested on. Older OpenChamber versions refuse to install it and show their usual version message.
- **Moving from the old Setup install takes one confirmed step.** If you installed the companion with an earlier version's Setup, that global copy keeps recording, even with the extension switched off, until you move. Setup detects it and offers to remove it and switch to the managed companion in one confirmed step, keeping your history. Setup no longer updates the old global copy, because the new companion cannot run from it. If the move is interrupted, capture stays off and Setup explains how to finish it.
- What is captured: sessions in the OpenCode that OpenChamber runs. OpenCode started in a terminal, isolated spaces, remote servers and VS Code are not captured.
- Integrity is now a warning, not a guarantee. OpenChamber does not check the companion's files. Agent Progress records what it expects and warns when the loaded companion differs, but it does not stop it from running. This is weaker than the earlier Setup install, and the setup guide explains the difference.
- Built against the extension SDK 2.7.0 and tested on OpenChamber 2.7.1 for the web with OpenCode 2.2.7 on Linux. Windows and the desktop app were not run natively; the compatibility guide records what was covered.
