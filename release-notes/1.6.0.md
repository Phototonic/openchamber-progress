# Read the plan, hide quiet plans, and see who reported what

## New

- **Rail and board: read the plan document beside Map and List.** The **Plan document** button opens a read-only preview of the saved capture. Markdown shows headings, lists and read-only checkboxes. Raw HTML stays as text, and the preview loads nothing from the web. A very large or complex document shows as plain text instead, so the panel stays responsive. Web links open outside the preview only when you activate them; if a link can't be opened, you see an error. (thanks to [@Vnuchoke](https://github.com/Vnuchoke))
- **Rail and board: spot quiet plans, hide them, or finish them as cancelled.** After seven days without a stored report, an active plan shows how long it has been quiet; that label never means the plan is done or abandoned. The filter is on by default, and you can turn it off to see all plans. To close a plan deliberately, choose **Finish as cancelled** from its More menu and confirm. Only the coordinating agent can reopen it.
- **List: open Activity to see who reported what and when.** On the rail or board, browse a plan's recorded updates, see who reported or relayed each one, and read the task IDs they named. Cancellations you confirmed are marked separately.

## Fixes

- **Setup: know what to put in Progress folder.** Setup now says to leave it empty for the recommended private folder and shows which folder that is. A custom folder must be a full path to a private folder in your account; a relative path or a refused folder now gets a plain explanation. (reported by [@ShalokShalom](https://github.com/ShalokShalom))
- **Setup: keep working after a reboot changes the drive's device number.** On btrfs and similar file systems, a completed setup could stop working after a reboot and the panel said Progress wasn't responding. Setup now recognises it's still the same store and keeps working; existing installs recover after updating. When Setup does refuse, the panel now says it couldn't verify the setup and points you to **More → Setup**. (reported by [@PhilippLoewen](https://github.com/PhilippLoewen))
- **Setup: pick up where it left off if the first save was interrupted.** If Setup is stopped during its very first save, it now recognises what it left behind and offers **Continue**, instead of leaving you to fix files by hand. A folder Setup can't confirm as its own still needs manual attention.
- Setup: the first save now works on systems that don't report when a file was created, such as some containers and older kernels. Before, Setup could stop there with a leftover temporary file and refuse to continue.
- **Setup: see the status and next action first.** Setup now leads with what needs attention and what you can do next. Technical notes are available in a collapsed **Details** section.
- Board: when the quiet filter hides every plan, you see one message with **Show all plans** instead of two empty messages.
- Composer: a plan you finished as cancelled can still be mentioned, also after it is reopened. Before, picking it showed an error.
- Setup: the finished card explains when recording can't be confirmed because Setup couldn't read the current status. You can still choose **Check status**.
- Setup: **Review configuration** waits for the panel's own status check instead of asking you to try again.
- Rail and board: when Progress is busy, the panel says so instead of saying it isn't responding.
- Rail and board: More stays open when the panel refreshes.
- Board: bulk cleanup results stay visible while the list refreshes, so you can see what succeeded, what was skipped, and what couldn't be confirmed.
- History: **View current task** opens List and focuses the task again.
- Companion: after a sub-agent is unlinked or its plan is deleted, old assignment notes stop being repeated once the companion confirms the sub-agent has no assignments left.
