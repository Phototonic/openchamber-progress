# A roomier dependency map and quieter sub-agent warnings

## New

- **Dependency map: arrows show what is working and what is blocked.** An arrow from a task reported as working carries blue beads that travel toward the task waiting on it, and an arrow from a blocked task turns into a warning-coloured line with a stop bar. You can see where a plan is moving and where it is stuck without opening a single card. Motion pauses when capture is off, when the view is hidden, on very large plans, and when your system asks for reduced motion.
- **Board: the map uses the width of a wide screen.** The board is no longer held to a narrow centre column, so a plan that used to fit at about a third of its size is now readable. Task details open as a panel over the map's right edge only while a task is selected, and the map keeps the selected card in view.
- **Sub-agents: one quiet cue replaces the standing warnings.** Routine notes about partial coverage used to sit under Sub-agents as orange lines almost all the time. They now live behind a small **Partial** badge beside the counts, which opens the full notes and the Load more history action in place. Notes about something that is broken right now still show on their own line.
- **Sub-agents: recording gaps are dated and can be dismissed.** The note about runs that were not recorded used to stay forever after a single failure. It now says when a gap was last detected, turns the badge orange only for a gap from the last 24 hours, and offers **Dismiss warning**. Older and dismissed gaps stay listed with their date, so the counts are never presented as complete when they are not.
- Dependency map: click the empty background or press Escape to clear the selected card and its highlights. The view stays where you left it.
- Dependency map: the keys, definitions and caveats moved into a **Map help** section you can open and close, so the map starts with more room.

## Improvements

- Progress bar: the segmented bar follows the look of OpenChamber's own progress bar, with a slimmer track and rounded segments. A plan with every task done shows its count in the success colour with a done mark.
- Board: on a wide screen, Fit all stops at 100%, so a small plan is not blown up past its natural size.
- Work Status: a long plan title wraps to use the available width, and the plan picker moves below it when there is no room beside it.
- Sub-agents: if you move by keyboard and a background update removes the control you were on, focus moves to the nearest control that is still there.

## Fixes

- Setup: when the installed version meets progress data saved by a newer version, the views now say "Progress data needs an update" and keep Setup reachable. They used to say the service might still be starting, which retrying could never fix.
- Setup: installing or updating the companion is refused up front when the saved data is in a format the installed version does not support, and nothing is changed. Capture is no longer switched off as a side effect.
- Setup: progress data from an early pre-release build, which only the companion can upgrade, no longer blocks the views or the companion update that upgrades it.

## Misc

- **Upgrading from 1.0.0: restart OpenCode after updating the companion, and note that this step is one-way.** The first time the updated companion loads, it upgrades the saved sub-agent run data to a new format. Plans, history and recorded runs are kept. Nothing is upgraded until OpenCode loads the new companion, so the views keep working in between. After the upgrade, version 1.0.0 can no longer read that data: its views show "Progress service is not responding" until you install 1.1.1 or later again. Restart any OpenCode instance that still has the older companion loaded. The setup guide has the details.
- A recording gap from before the update has no known date. It is listed as "This happened before the update; the date is unknown." and does not raise the warning.
- Version 1.1.0 reached the main branch but was never published as a release: the release tooling could not read one of the built files once it grew past 1 MiB. Version 1.1.1 is the same set of changes with that fixed, and is the first published release after 1.0.0.
- Built against the extension SDK 2.7.0. The upgrade from 1.0.0 and the return to 1.0.0 were rehearsed on an isolated OpenChamber 2.7.0 desktop host with OpenCode 2.2.6; the compatibility guide records what was and was not covered.
