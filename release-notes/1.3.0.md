# Progress from the sub-agents doing the work

## New

- **Reporting: sub-agents can report their own assigned tasks.** Their direct reports are attributed to the sub-agent in the rail and dependency map, so you can see who reported the work instead of relying on the coordinator to relay it. This becomes available only after the dispatch is bound to the assigned tasks; starting a sub-agent alone does not change progress. A sub-agent can also combine its final task update and handoff in one report. A handoff without task updates remains a claim, not task completion.
- **Sessions: Open Agent Progress for the session you choose.** The session menu opens that session's progress in the rail, even when you are chatting elsewhere. Use **Show current session** to return to the chat you have open. Closing and reopening the panel in OpenChamber 2.7.1 keeps the chosen session; it does not reset the view. After a reset, choosing the same session's action again may leave the view on the current chat. Choose a different session's action first, then the original, or reload OpenChamber. This is a host limitation, not a missing progress report ([openchamber#6938](https://github.com/openchamber/openchamber/issues/6938)).

## Improvements

- Reporting: after a sub-agent dispatch, the hint the agent sees now says plainly what to do. If the work has no plan yet, start one before dispatching more, and declare the task assignments before the next dispatch so the sub-agents can report their own tasks. It is still only advice: nothing starts a plan or reports progress for the agent.

## Fixes

- Reporting: a `change` that names a group or an unknown item is still refused, but the reply now says why: `change` updates existing tasks only, and a group's status or the plan's structure is changed with `revise`.
- Sessions: the expanded Sessions panel now has a single heading, without losing its participant or session details.

## Misc

- **Still requires OpenChamber 2.7.1 or later.**
- Tested on OpenChamber 2.7.1 for the web with OpenCode 2.2.7 on Linux. Windows and the desktop app were not run natively; the compatibility guide records what was covered.
