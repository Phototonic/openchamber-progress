# Simple by default

## New

- **Progress: plans open on a readable map.** The board brings current work into view when the whole plan would be too small, with Fit to see every task and one Map | List switch.
- **Needs you: a compact list keeps questions for you separate from blockers between agents.** It starts with the selected session's plans, with Open session, Copy reply and Hide on each item; a link lets you check other plans. Only decision or review blockers reported by a plan's top-level main session appear here. Hidden items stay hidden on this device until the agent reports a change.
- **Tidy: archive finished and cancelled plans together, with Undo.** The More menu lets you tidy up to 50 plans from the current list after confirmation, without deleting them. Failed plans stay out of Tidy and can still be archived individually.

## Improvements

- Work Status: five short lines replace the crowded card, showing the plan, progress, running agents and questions for you, any stale report or recording problem, and Open progress.
- Progress: one calm incomplete-counts indicator replaces scattered coverage notices. Counts that may be low carry a plus sign, even when you dismiss the indicator.
- Navigation: one More menu holds History, the plan document, Sessions, language, Setup and Troubleshooting. Panels open in place with Back, leaving the default screen focused on the work.
- Setup: fresh setup is presented as four plain steps: create a private progress folder, connect it to OpenCode, turn on recording and check that it works. Technical details sit in one disclosure; consent and recording state stay visible.
- Languages: clearer everyday wording across the interface in English, Russian and Simplified Chinese keeps technical details in Troubleshooting rather than on the main screen. Saved plan and task text stays as written.
- Reporting: plan-mirroring guidance now reaches agents through tool descriptions and eligible tool results, even when a provider drops added system text, without custom instructions. It also recognises OpenSpec plans and plans in sibling worktrees. Reports still depend on the agent following that guidance; nothing is reported automatically.

## Fixes

- History: long plans show the newest updates first, rather than the oldest loaded updates. Up to 250 recent updates are shown, with a note when older ones are left out.
- Cleanup: cancelled and failed plans can now be archived, restored or permanently deleted individually, just like finished plans. Restoring keeps the plan's original outcome; active plans still cannot be cleaned up.
- Setup: closing the panel stops it from queuing more steps; a step already sent can finish, and reopening offers Continue. Changing recording inside Setup no longer closes the panel.

## Misc

- Installation: `dev` is now source only and no longer tracks built files; those are produced when promoting to `main`. `#dev` Git installs are no longer offered or supported. If you installed from `#dev`, replace that installation with one from the default branch or a release tag; updates from the source-only branch are refused and keep the previous installed files.
- CI: Windows checks skip interface-only pull requests, while the slow migration and delayed-setup journeys run for promotions, `main` pushes, weekly checks and manual runs. Documentation-only pull requests also skip checks that cannot validate their changes; release publication still requires the full Windows job.
- Compatibility: still requires OpenChamber 2.7.1 or later. The reporting protocol and storage schema remain at version 2.
