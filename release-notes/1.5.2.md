# A stable system prompt, and steadier Tidy

## Improvements

- **Companion: the system prompt section is now stable, so providers can keep caching your conversation.** The section used to change between requests: after a dispatch or a plan write, in a sub-agent session and after a delegation refusal. A provider's prompt cache misses from the first change onward, which a user reported as a lower cache hit rate (#161). The section is now identical on every request. The notes that vary between requests arrive after the cacheable part, on the latest message, and stay in place on later requests. Providers that drop plugin system text now receive those notes too. Tests check that each request begins with the previous one byte for byte; real cache hit rates depend on the provider and were not measured.
- **Full page: the Tidy and selection result tells skipped plans from plans it could not confirm.** A request whose reply never arrived may have been applied, so the result line now says so in English, Russian and Simplified Chinese instead of calling the plan skipped. Undo still restores only plans whose archive was confirmed.

## Fixes

- **Windows: the companion no longer freezes OpenCode.** On Windows the companion started PowerShell to check folder permissions when it loaded, on tool calls and on every status poll. That could block OpenCode for 28 to 43 seconds, leaving the model list empty, `/api/provider` answering 503 and sessions timing out (#172). The companion now starts no process for permission checks on any platform, so loading, tool calls and status polls no longer wait on one. Agent Progress no longer checks Windows folder permissions: Windows relies on your profile's default per-user permissions, and a store or custom folder that other users can write to is now accepted. Link, path, marker and schema checks remain, Linux and macOS checks are unchanged, and existing installs keep working. (thanks to [@NOMOO8](https://github.com/NOMOO8))
- Full page: a Tidy or selection run that finishes after you switch account or store no longer resets or changes the board you switched to, and Tidy and Select work at once on the new board. Cleanup controls follow what the service currently offers, including after a failed list read or a switch between Current and Archived plans.
- Full page: a count, a run's progress or its result arriving in the background no longer cancels a click or a press on Stop, and a focus move Tidy queued no longer pulls focus away from a control you chose. A result you have not seen yet is no longer dropped by the next refresh.
- Full page: Tidy and Select all now say when their count may have missed plans, which can happen when the plan list was read in more than one page. A count from a single page, or from rows you chose yourself, stays exact. A selection made during a search follows plans archived, deleted or restored elsewhere, and a plan restored elsewhere is counted again by the next action.
- Reporting: when work moves back to the prerequisites of a task an agent reported blocked, agents are now told to read the current plan and clear the block once every prerequisite the task still lists is done, instead of waiting on a prerequisite the plan no longer has. Coordinator guidance no longer turns a malformed delegation receipt into a confident refusal.

## Misc

- Documentation: clarifies when Tidy and Select all check chosen plans one by one and which revision a retry compares against.
- Development: the large-library check counts the requests a measuring window actually sent and reports a comparison it could not make as unverified instead of passing it.
- Development: the Linux test step in CI is faster, dropping from about 5 minutes to about 2.5 to 4 minutes, with no tests removed. New `bun run test:fast` and `bun run test:all` commands run the portable checks locally. The runner is POSIX-first, and stopping it on Windows is best effort.
